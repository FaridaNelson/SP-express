## Permission Resolution

Resolved Linux container permission issues.

### Problem

OpenClaw container user:

```text
uid=1000 (node)
```

Repository owner:

```text
uid=1001 (faridanelson)
```

The agent had read access but could not modify files.

### Solution

Added supplemental Docker group:

```yaml
group_add:
  - "1002"
```

allowing the container user to write to the mounted repository.

Verified:

```text
Write access confirmed
```

without changing repository ownership.

# Authorization

Implemented student self-access.

Authenticated user:

```text
JWT
```

↓

Resolved through:

```text
Student.studentUserId
```

↓

Mapped to:

```text
GameProgress.studentId
```

Students may only access their own GameProgress.

Teacher and parent access remain future work.

## cumulativeStats validation

Implemented protection against:

```text
$
.
empty keys
```

---

## Partial updates

Refactored updates to use dotted MongoDB paths.

Example:

```text
cumulativeStats.C4.seen
```

instead of replacing the entire object.

Result:

Updating one note no longer overwrites other accumulated statistics.

The same approach was applied to:

```text
cycleContext
```

allowing partial updates without replacing the entire object.

# API Review

Reviewed response conventions across the StudioPulse backend.

Compared:

- Student
- Practice Log
- Exam Cycle
- Parent
- Score Entry

Decision:

Return:

```json
{
  "gameProgress": ...
}
```

instead of:

```json
{
  "progress": ...
}
```

to clearly distinguish GameProgress from future exam progress endpoints.

# Security

Added a narrow pre-sanitize validation step.

Purpose:

Reject unsafe cumulativeStats keys before MongoSanitize silently strips them.

Scope limited to:

```text
/api/game-progress/*
```

The existing global MongoSanitize middleware remains unchanged.
